Gradient descent

Why a bigger step can make things worse

Every weight in a trained model was set by the same small loop, run millions of times. One number in that loop decides whether training settles, crawls, or blows up.

Where the weights came from

If you have served a large model, you have handled its weights: sharded them across GPUs, streamed layers through a pipeline, budgeted memory around them. Billions of numbers, and inference only ever reads them.

Before training, every one of those numbers was random, and the model produced noise. Training is what turned the noise into weights worth serving, and it does that with a loop small enough to fit in four lines:

  1. Run the model forward on an example, exactly as inference would.
  2. Score how wrong the output was. That score is the loss.
  3. Work out, for every weight, which way to nudge it so the loss goes down. Together those directions are the gradient; computing them is the backward pass.
  4. Nudge every weight a little in its direction. How far is set by one number, the learning rate.

One trip around the loop is a step, and a training run is millions of steps. Before handing the loop over to the machine, run it yourself on a model with a single weight.

Keep dragging until the right-hand chart shows a shape. Each setting you try leaves a dot, and the dots trace a bowl. The bottom of the bowl is the best weight this data allows, and getting there is all that training is for. When you dragged toward the bottom, you were following the gradient by feel: which way the loss falls, and how steeply.

A real model can't do it that way, for two reasons. It has billions of weights, so nobody drags them; the backward pass computes every weight's direction at once. And it never sees the whole bowl. It only knows the slope where it is standing, so it steps, looks again, and steps again. How long each step should be is the rest of this page.

One step at a time

Keep the shape and drop the units: a bowl whose bottom sits at w = 3, like the one you just traced.

L(w) = (w − 3)²

Gradient descent looks at the slope where it stands and steps the other way, by an amount scaled by the learning rate η:

w ← w − η · L′(w)

Each update moves w by η · 2(w − 3), so the distance to the bottom gets multiplied by the same number every step: 1 − 2η, shown above the figure. With a small rate that number is just under 1, and the ball creeps. Try 0.05, then 0.3.

Predict first

At η = 0.9 the first step carries w past the bottom, onto the other wall. What happens after that?

It bounces and settles.

The multiplier is 1 − 2 × 0.9 = −0.8. The minus sign flips w to the other side of the bottom every step; the 0.8 still shrinks the distance. Overshooting is not failure, as long as each overshoot is smaller than the last.

Predict again

Now η = 1.1, only a little bigger. What happens?

Each bounce grows.

The multiplier is now −1.2: every step lands farther from the bottom than the one before, and the loss grows without bound. The first step alone goes from 0 to 6.6. A slightly bigger step size turned a working optimizer into a diverging one.

Every learning rate at once

A single run tells you about a single η. To see the pattern, step up a level: run the same twenty steps for every learning rate from 0 to 1.2, and plot only where each one ends.

The whole story is in that shape. Below 0.5, bigger is better: the ball creeps faster. At exactly 0.5 the multiplier is zero and a single step lands on the bottom, which is the dip to “≈0”. Between 0.5 and 1 the ball overshoots but still settles. At 1 the multiplier reaches −1, and past it every step makes things worse. There is no gentle decline at the edge; it is a cliff.

The edge depends on how steep the bowl is. For a bowl a times steeper, L = a(w − 3)², the multiplier becomes 1 − 2aη and the cliff moves to η = 1/a. Steeper ground demands smaller steps.

Two directions, one step size

A real model has millions of parameters, and its bowl is rarely round. Here are just two, x and y, in a valley ten times steeper across than along:

Predict first

The steep direction diverges at η = 0.2, so set it just under that, at 0.19, to go as fast as possible. Which direction is still far from the bottom after forty steps?

The steep direction lags.

Across the valley the multiplier is |1 − 10 × 0.19| = 0.9, so the ball zigzags from wall to wall and the zigzag fades slowly. Along the valley it is |1 − 0.19| = 0.81, which is faster. Pushing toward the steep direction's limit made it the slow one.

The best single rate balances the two, where 1 − η = 10η − 1, giving η = 2/11 ≈ 0.18. Even then each step removes only about 18% of the remaining distance. The steeper the valley compared with its floor, the worse this gets. That ratio is called the condition number, and it is why optimizers such as Adam give each parameter its own effective step size.

Where this model stops. Real losses are not perfect bowls: the steepness changes as the parameters move, so a rate that is safe in one place can be too large in another. Real gradients are usually estimated from a small batch of data and are noisy. Schedules that change the rate over time, warmup, and momentum all exist to handle these effects. The bowl is the picture close to a minimum, where the same arithmetic holds. For a fuller treatment, see Dive into Deep Learning §12.3.

Try it without the page

For L(w) = 3(w − 1)², what is the largest learning rate that still settles, and which rate reaches the bottom in one step?

The slope is 6(w − 1), so each step multiplies the distance to the bottom by 1 − 6η. That settles while |1 − 6η| < 1, so η < 1/3. One step lands exactly when 1 − 6η = 0, at η = 1/6. The rule from the bowl holds: for a bowl three times steeper, everything happens at a third of the rate.
